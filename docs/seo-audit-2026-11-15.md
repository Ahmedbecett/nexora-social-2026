# NEXORA AI — technical SEO implementation and verification

**Audit date:** 2026-11-15 · **Canonical site:** https://nexora-social-2026.vercel.app/

**Product scope:** the deployed app is the NEXORA **AI workspace**, not the retired social feed/reels/messaging UI. This report does not claim the site is a live social network or promise rankings.

## Before these changes

- The production homepage rendered primarily as sign-in after JavaScript loaded; the unhydrated HTML had a short AI description and an inert `#root` link. It also described the Android APK as **0.5 MB**, while the checked-in file is **13,814,604 bytes** (13.8 MB).
- The English `hreflang` pointed at `/?lang=en`, which returned the same app document/canonical as `/`, not a distinct English information page.
- The XML sitemap listed only `/` and `/privacy.html`; `/about` returned 404. Privacy had Arabic and English H1s on the same Arabic document. The homepage advertised FAQ structured data whose answers were not visible after the app hydrated.
- The app boot loaded its Markdown/KaTeX/highlighting dependencies and a remote Google Fonts CSS request. AdSense was fetched on sign-in even without an ad slot.
- `robots.txt`, the Google HTML verification file, `/privacy.html`, and the production `/api/health` endpoint were publicly reachable at the time of the audit. This **does not** prove Google Search Console ownership or successful indexing.

## Implemented in this repository

1. **Crawlable, unique content:** Arabic app homepage plus a dedicated English homepage, About, Features, Download, FAQ and Privacy pages in both Arabic and English (**12 canonical URLs**). Static information pages have useful, original product explanations and require no JavaScript, login, mock responses or database access. The signed-out React homepage now keeps a visible informational section after hydration; the Android authentication experience is not replaced.
2. **Metadata:** unique titles/descriptions, self-referential canonicals, indexable robots meta, complete reciprocal `ar`/`en`/`x-default` alternates, Open Graph and Twitter cards for every public page. The home title is evergreen rather than changing each app release. Old `/?lang=en` remains canonicalized to `/` rather than being listed as an alternate.
3. **Structured data:** accurate Organization, WebSite, WebPage and SoftwareApplication data on the homepage; WebPage/AboutPage and breadcrumbs on relevant static pages; FAQPage **only on the FAQ pages**, with the exact questions and answers visible to visitors. Software version comes from `package.json`; Android minimum requirement matches minSdkVersion 23 (Android 6.0+). No fabricated reviews, ratings or social product features.
4. **Crawl control:** `robots.txt` allows pages/assets and disallows API URLs; `sitemap.xml` lists the 12 canonical URLs with language alternatives and substantive last-modified date. Firebase hosting's alternate sitemap/robots files are kept synchronized. Vercel permanently redirects extensionless guide URLs to their canonical `.html` URLs and marks API responses and APK downloads `X-Robots-Tag: noindex`. Existing `/api/:path*` rewrite and APK attachment/MIME headers are preserved.
5. **Performance:** public information pages load a 4.5 KB local CSS file and no app JavaScript. A local Cairo variable font replaces the blocking external Google Fonts CSS on the app. Markdown, math rendering, syntax highlighting and the owner dashboard load only when used. AdSense loads when a real authenticated web ad slot mounts; it remains excluded from native WebViews. WebP assets replace the large PNG mascot/avatars in the UI, and a compressed JPEG is used for social cards. Native/PWA PNG icons and original files remain available. Versioned `/assets/*` files receive immutable cache headers; unversioned new assets have a one-day cache.
6. **Content accuracy:** the FAQ explicitly distinguishes this AI chat application from a social networking app. No keyword stuffing or claims that a social feed, direct messaging or reels currently operate. The download page links to the **real** APK and computes its approximate size from the packaged file. Legal/privacy claims were preserved while English and Arabic policy pages were separated.

## Verification and measured results

- `npm run build`: **pass** (Vite production build, approx. 5 s on the local runner).
- `npm test`: **55/55 pass**, including new tests for generated-page synchronization, metadata uniqueness, reciprocal hreflang, JSON-LD/visible FAQ, links/assets, sitemap coverage, headers and built output.
- Local production-build HTTP smoke: all **12 HTML pages**, robots, sitemap, CSS, compressed images and verification file returned **200**; XML parsed with **12** URLs; APK `HEAD` returned **200** and **13,814,604 bytes**. Vite's local preview does **not** apply Vercel-specific redirects or HTTP headers; those require a Vercel deployment test.
- Initial app JS entry: **~816 KB → 314 KB minified** (the new entry is **101 KB gzip**); the **511 KB** Markdown JS chunk is now lazy. Initial app CSS: **~144 KB → 118 KB minified**, with the Markdown-specific **31 KB** CSS loaded on demand. Sizes are build-output sizes, not browser timings.
- Mascot served to app: **395,951 → 10,592 bytes** (−97%). Chat avatar: **103,387 → 3,456 bytes** (−97%). OG image: **484,021 → 80,531 bytes** (−83%), still 1200×630. Static HTML pages range from roughly 6–10 KB and use a 4,515-byte stylesheet.
- **Core Web Vitals (field LCP, CLS, INP) and Lighthouse scores are not measured here.** This environment has no browser/CrUX data or authorized PageSpeed Insights report; build bytes and local response success do not substitute for real-user metrics.

If social functionality is restored in a future release, write and index relevant pages only after the features are actually public.

### Maintenance

Edit the human-written copy in `scripts/generate-seo-pages.mjs`, update its `lastmod` only when copy changes, and run `npm run generate:seo`. Commit the generated files in `public/`. `npm run build` regenerates them before Vite copies them to `dist/`, and the SEO tests fail if tracked files drift. **Keep the generator in the Vercel upload**: excluding the `scripts/` directory via `.vercelignore` makes the Vercel build fail before Vite runs (the first PR preview exposed this and the exclusion was removed). The existing `public/privacy.html` and `public/en/privacy.html` are maintained as legal copy separately. Recheck their bilingual hreflang and the sitemap when changing paths.
