# Adsterra Native Banner web rollout — 15 November 2026

The owner supplied an Adsterra-style Native Banner script at `https://bauval.org/21/5641403c5558334d50a26de1c90fe61d` and its matching `container-5641403c5558334d50a26de1c90fe61d`. They chose **all normal website views**, including sign-in, registration and signed-in chat, and explicitly chose to keep the existing AdSense slots alongside it. The script URL and zone came from the owner; this repository cannot verify ownership, provider approval, ad fill or payment.

- The 11 static HTML pages have one in-body Native Banner container near the hero and the SPA at `/` renders one container in its sign-in/registration view or at the top of the signed-in scroll area. The old AdSense `AdSlot` remains separate in signed-in home/chat. Splash and PIN lock overlays are transient views with no Native Banner placement.
- Each HTML entry references the same deferred first-party `/adsterra-web.js` bootstrap. It injects the **exact owner-provided HTTPS URL** as an asynchronous script with `data-cfasync="false"`, immediately before the matching container. On the SPA, it waits for React to mount and requests the zone once for that container; home/chat updates reuse the same container. A real sign-in/sign-out view change replaces the container and may cause a new provider request, which must be checked against the provider's SPA guidance.
- The external script is excluded on localhost/preview domains, non-HTTPS origins, native Android WebViews and browsers signaling Global Privacy Control. The native AdMob integration, Monetag's separate OnClick tag, authentication, APIs and database are not altered. `/adsterra-web.js` revalidates on Vercel for quick fixes.
- Both privacy pages now disclose Adsterra and the scope of third-party script access. As with Monetag, this unsandboxed script runs with the page's privileges and may technically read login inputs, locally stored tokens and private chat content. `async`, HTTPS and referrer policy **do not sandbox it**. GPC blocking is not a consent management platform; obtain legal/CMP and ad-network policy review for applicable audiences before relying on this setup.

After release, with a real authorized account, manually inspect public pages, sign-in, registration, signed-in home/chat, login-to-chat transition, mobile sizing and browser ad blocking. Do not click live ads or generate synthetic traffic. If no creative appears, verify the zone is Active and approved in the Adsterra dashboard, then inspect browser network/console errors; an empty container is not proof of an integration failure. If the provider script interferes with authentication or private content, pause it in the Adsterra dashboard and remove the bootstrap in a subsequent release.

Adsterra's [Native Banner placement guidance](https://adsterra.com/blog/turn-a-profit-with-native-banners/) places the tag in the HTML body. The owner-provided `bauval.org` script was inspected as text only; its account ownership was not independently confirmed.
