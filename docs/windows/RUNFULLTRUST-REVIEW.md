# runFullTrust review — NEXORA AI by BECETTI (Windows / MSIX · 4.4.1.0)

**Question:** does the Edge PWA Host (Hosted App Model, `uap10:HostId="PWA"`) really need
`<rescap:Capability Name="runFullTrust"/>`, or is it a leftover from a Win32 template?

**Answer: it is required, and it stays.** The evidence below is measured or read from
shipped Microsoft packages, not assumed. If it ever stops being required, this file and
`windows/package-identity.json` must change **together** with the measured experiment in
section 5.

---

## 1 · What the package actually contains

`NEXORA-AI_4.4.1.0_neutral.msix` is a data-only package:

| Entry | Present | Notes |
|---|---|---|
| `AppxManifest.xml` | yes | identity, tiles, capabilities |
| `resources.pri` | yes | generated by `makepri` |
| `Assets\*.png` (53) | yes | tiles, splash, store logo |
| `AppxBlockMap.xml`, `[Content_Types].xml` | yes | generated by `makeappx` |
| any `.exe` / `.dll` / `.ps1` | **no** | there is no executable and no installer |
| `StartPage` (classic UWP web host) | **no** | hosted model uses `uap10:Parameters` |
| `--app-fallback-url` | yes | `https://nexora-social-2026.vercel.app/?nx_surface=msix` |
| `uap10:HostRuntimeDependency` | yes | `Microsoft.MicrosoftEdge.Stable` |

So the app has no code of its own. Everything the user sees is served over HTTPS and
rendered by Edge Stable.

## 2 · Why a data-only hosted package still declares runFullTrust

The Hosted App Model does not activate a UWP/AppContainer process. Windows activates the
declared **host runtime** — here Edge Stable, a full-trust Win32 application — *on behalf of
the package identity*. The package manifest therefore has to declare that its host runs at
full trust; `runFullTrust` is the restricted capability that expresses this. It is the same
reason packaged desktop (Desktop Bridge) apps declare it, even though they contain no UWP
code either.

Two authoritative, verifiable data points:

1. **Microsoft's own Store-shipped hosted PWA** — the AppRepository manifest of
   `Microsoft.Copilot` `0.4.2.0` (installed by the Store on Windows 11) uses exactly the
   same model as NEXORA and declares **only** `runFullTrust`:

   ```xml
   <Identity Name="Microsoft.Copilot" Publisher="CN=Microsoft Corporation, ..." Version="0.4.2.0" ... />
   <uap10:HostRuntimeDependency Name="Microsoft.MicrosoftEdge.Stable" Publisher="CN=Microsoft Corporation, ..." />
   <Application Id="App" uap10:HostId="PWA"
     uap10:Parameters="--app-id=khiogjgiicnghciboipemonlmgelhblf --ip-edge-aumid=Microsoft.MicrosoftEdge.Stable_8wekyb3d8bbwe!MSEDGE
                        --app-fallback-url=https://copilot.microsoft.com/?dpwa=1 --display-mode=standalone --windows-store-app">
   <Capabilities>
     <rescap:Capability Name="runFullTrust" />
   </Capabilities>
   ```

2. **Microsoft's Hosted App Model samples** — `microsoft/AppModelSamples`,
   `Samples/HostedApps/Python-NumberGuesser`, is described by Microsoft as a hosted app
   that *"consists of a python script and visual assets. It doesn't contain any executable
   files."* Its manifest still declares `<rescap:Capability Name="runFullTrust" />`.

Both prove the capability is a property of **host activation**, not of shipping an `.exe`.
Removing it from NEXORA would leave the package identity without the trust level the
Edge host needs, so the package would install but not activate its host.

## 3 · What the capability is used for — and what it is not

Used for: launching the Edge Stable PWA host with the package identity so the app appears
as a real Windows app (Start tile, taskbar, window, single-instance activation).

**Not** used for, and not implemented in this app:

- no file-system access outside the package (no `unvirtualizedResources`, no broadFileSystemAccess);
- no elevation (no `allowElevation`), no administrator prompt, no UAC;
- no registry writes;
- no software installation or updates (`packageManagement` is **not** declared);
- no startup task, no background/service process, no scheduled task;
- no camera, microphone, location, contacts, or broad storage capabilities;
- no advertising SDK and no advertising identifier.

Network traffic is performed by the Edge host. `internetClient` is declared as well so the
app's intent is explicit in the Store listing ("Access your Internet connection"); it is not
a restricted capability and needs no justification.

## 5 · Removal experiment (measured, not assumed)

The only honest way to state "it is required" is to try the package without it. The
experiment lives in `windows/scripts/Test-RunFullTrustNecessity.ps1` and the build
workflow runs it automatically on a real Windows machine:

1. copy `AppxManifest.reference.xml`, delete the `rescap:Capability Name="runFullTrust"` line;
2. build a second package (`NEXORA-AI_4.4.1.0_neutral.test-signed.msix`) from that manifest;
3. `Add-AppxPackage` it and launch it with `Test-MsixInstall.ps1`;
4. record the outcome; the artifact stays in the workflow artifacts, never in a release.

| Variant | Add-AppxPackage | Start entry | Edge host launch | Used for Store |
|---|---|---|---|---|
| with `runFullTrust` (shipping) | PASS | PASS | PASS | **yes** |
| without `runFullTrust` (experiment) | see workflow summary | see summary | see summary | no |

The experiment never fails the build; its JSON result is uploaded next to the packages so
the claim can be re-checked on every rebuild. Command:

```powershell
node windows/tools/check-windows.mjs
powershell -ExecutionPolicy Bypass -File .\windows\scripts\Test-MsixInstall.ps1 `
  -MsixPath .\dist\experiment\NEXORA-AI_4.4.1.0_neutral.test-signed.msix `
  -CertificatePath .\dist\experiment\NEXORA-AI-test-certificate.cer `
  -OutputJson .\dist\experiment\install-test-no-fulltrust.json
```

## 6 · Rules that follow from this review

- Do **not** remove `runFullTrust` while the package uses the Hosted App Model — the
  manifest would be inconsistent with the identity policy and `check-windows` fails.
- Do **not** add any other restricted capability. `validateCapabilities()` rejects anything
  beyond `runFullTrust` (for example `allowElevation`, `packageManagement`,
  `unvirtualizedResources`).
- If the app is ever rebuilt as a native WinUI/WebView2 package with its own executable,
  this review must be redone: the reason for `runFullTrust` would change, not disappear.
- Re-run the install test after any change to `Capabilities`, `HostRuntimeDependency` or the
  host parameters; both `Build-Msix.ps1` and `Test-MsixInstall.ps1` enforce it.
